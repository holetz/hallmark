## Problem

The 2026-10-25 review of PRs #8–#12 found eight defects. The conductor reproduced the first: with `HALLMARK_DBX_HOST=adb-x.example.invalid`, the client raises `ValueError: unknown url type: 'adb-x.example.invalid/api/2.1/jobs/list'`.

1. **Host echoed in errors (security).** `hallmark/databricks_client.py:65` and `mlflow_client.py:54` build `Request` outside the `try`. `ops_mcp.py:307-308` and `models_mcp.py:260-261` return `str(exc)` as tool text, which contradicts `databricks_client.py:6` and `README.md:64`. Fix: validate and normalize the host once at construction, adding `https://` when the scheme is missing and refusing anything that is not `https`. Every client error must carry a fixed message plus the path only.
2. **The index is not ignored (security).** `__main__.py:13` writes `.hallmark/index.db` inside the repo, and `.gitignore` does not cover it. The index holds real catalog names. Fix: add `.hallmark/` and `*.db` to `.gitignore`, and make `refresh` refuse a `--db` that git tracks or does not ignore.
3. **Unquoted catalog identifier in SQL (security).** `connectors/unity_catalog.py:94,97` interpolate `{catalog}` raw. Fix: backtick-quote it, doubling any backticks, and validate it. Test with `demo-sales`.
4. **Page caps fail instead of truncating (correctness).** `databricks_client.py:84` raises after 20 pages, and `mlflow_client.py:84` does the same. `list_jobs` paginates everything before filtering by name on the client (`ops_mcp.py:126-127`), and `list_pipelines`/`alerts` have no cap. Fix: stop at the cap and report `truncated: true`, and send `name` to the server when filtering. This matches spec 5's Proposal: "every list is capped at 50 and reports `truncated`".
5. **Wrong argument types crash the servers (correctness).** In `ops_mcp.py:67,127,301`, `models_mcp.py:44,254` and `mcp.py:166,184`, a non-string filter or non-object `params` raises `AttributeError`, which kills the process. Fix: validate argument types against the declared schema and return a JSON-RPC error. Catch any exception per call, so the server never dies.
6. **`reruns` cut not reported (correctness).** `ops_mcp.py:183,195` never set `truncated` when more than 10 failed runs exist. Fix it as spec 5's Risks require.
7. **Docstrings claim conventions are "confirmed" (correctness).** `models_mcp.py:9` and `ops_mcp.py:9` say so, but `README.md:48,73-74` says "to confirm". Fix: state "assumption, to confirm against a real workspace" in the docstrings.
8. **Undocumented trace data (doc).** `README.md:68` must say that error traces may carry data a job printed.

Done when each item has a test, or for 7–8 a doc fix; the gate and CI are green; there is no CI-workflow or grant change; and no Databricks call is made.

## Proposal

- A malformed or non-https `HALLMARK_DBX_HOST` / `HALLMARK_MLFLOW_HOST` is normalized (scheme-less gets `https://`) or refused once, at client construction; no client or tool error ever carries the host, only a fixed message plus the path.
- `.hallmark/` and `*.db` are git-ignored, and `refresh` refuses a `--db` that git tracks or does not ignore.
- The Unity Catalog connector backtick-quotes (doubling backticks) and validates every catalog identifier it interpolates into SQL; a catalog named `demo-sales` works.
- A page cap truncates instead of raising: the listing stops at the cap and the tool reports `truncated: true`. `list_jobs` sends `name` to the server when filtering, and `list_pipelines`/`alerts` are capped.
- A non-string filter or non-object `params`/`arguments` yields a JSON-RPC error, and any exception inside one call is caught per call so the server process never dies.
- `reruns` reports `truncated: true` when more than 10 failed runs exist.
- The `models_mcp` and `ops_mcp` docstrings say the conventions are an assumption to confirm against a real workspace, and `README.md` says error traces may carry data a job printed.

## Out of Scope

- Any change to `.github/workflows/` or to a grant: ruled out by the conductor; if one turns out to be needed the run stops with needs-human.
- Any live Databricks, MLflow or model call: tests use the existing fixtures and stubs only.
- Raising `MAX_LIMIT` or changing the 50-item contract of spec 5: the fix aligns the page caps with it, nothing more.
- New tools or new REST paths on the allowlists.
- Rewriting the Unity Catalog `MAX_PAGES` (1000) behaviour for the snapshot connector: a refresh that silently truncated a catalog would be worse than failing, so it stays an error.

## Validation

- `bash scripts/verify_repo.sh` exits 0 and prints `verify_repo: green` (unit tests plus leak gates).
- With `HALLMARK_DBX_HOST=adb-x.example.invalid` the client builds `https://adb-x.example.invalid`; with `http://...` or `ftp://...` construction raises a `DatabricksError` whose text contains neither the host nor the token (tests assert this against the stub opener).
- A stub that always returns `next_page_token` makes `pages` stop at the cap with `truncated` reported, with no exception.
- A `tools/call` with `{"name_filter": 5}` or `"arguments": []` returns a JSON-RPC error or `isError` result, and a following request on the same stream is still answered.
- `git check-ignore .hallmark/index.db x.db` exits 0 and `refresh --db <tracked file>` exits non-zero.
- No test opens a socket: the stubs in `tests/_dbx_stub.py` and `tests/_mlflow_stub.py` are the only transports.

## Design

- **Host is validated once, in the constructor.** `_normalize_host(raw, error_cls)`: strip, add `https://` when no `://`, parse with `urllib.parse.urlsplit`, require scheme `https` and a non-empty netloc with no userinfo, query or fragment, rstrip `/`. The `ValueError`/`DatabricksError` text is a fixed message naming the env var, never the value. `Request` construction also moves inside the `try`, so no later failure can leak the URL.
- **Errors carry the path only.** `str(exc)` returned by `_call` is safe only when every raised message is fixed; client errors already are, and validation errors name argument keys, not values.
- **`pages` becomes an iterable that exposes `.truncated`.** On exhausting `MAX_PAGES` with a token pending it stops and sets `truncated = True` instead of raising. Tools combine it with `_cut`'s own flag: `truncated = cut.truncated or pages.truncated`. This keeps the call sites as `for x in pages(...)`.
- **Argument validation is table-driven from the declared schema** in `mcp.py` (one helper shared by the three servers): each property's JSON `type` is checked before the tool runs; a mismatch returns an `isError` result naming the key. `params` that is not an object, or `arguments` that is not an object, returns `-32602`. `_call` additionally catches `Exception` per call and returns a fixed `isError` text, never `str(exc)` for an unexpected exception type.
- **`list_jobs` sends `name` to the server** (the Jobs 2.1 list filter, case-insensitive exact match) and drops the client-side full scan; `list_pipelines` and `alerts` go through `pages`, bounded by `FETCH_CAP`, and report `truncated`.
- **`refresh` guards the index.** Before connecting, `git check-ignore -q` on the `--db` path (when inside a git work tree) must succeed and `git ls-files --error-unmatch` must fail; otherwise exit 2 with a fixed message. Outside a git repo the guard does not apply.
- **SQL identifier**: `_ident(name)` accepts `[A-Za-z0-9_-]+` plus any non-control text that survives backtick doubling, rejects empty and control characters, and returns `` `name` ``; the catalog literal in `WHERE` already uses `_sql_literal`.

## Alternatives Considered

- **Keep raising at the page cap and only document it.** Rejected: spec 5 promises truncation with a flag, and an exception turns a big workspace into a dead tool.
- **Redact the host from error text instead of validating it.** Rejected: the failure happens before the request exists, so redaction would still need the same try/except and would leave a malformed host accepted.
- **Validate arguments with a JSON-Schema library.** Rejected: the project has no runtime dependency by design.

Decided in the task 2.3: the tool description is changed to say exact name, and the README is aligned in 4.1. To be confirmed against a real workspace; the evidence is the Jobs 2.1 API reference, and the repo's tests use stubs only.
- Whether `refresh` should also refuse a `--db` outside a git work tree: decided no (the guard only applies inside one).

## Risks

- A stricter host check rejects a legitimate `http://` local MLflow server. ACCEPTED — the spec asks for `https` only; a local server can sit behind a TLS proxy. The refusal message names the env var so the cause is clear.
- The per-call catch-all could hide a real bug. Mitigation: it returns a fixed text and the test suite asserts the specific error paths, so a bug still fails a test; no value is echoed.
- `list_jobs` exact-name semantics change behaviour for users relying on substring. ACCEPTED — the server cannot do substring; the description states it.
- `.gitignore` of `*.db` hides a legitimately committed fixture database. Mitigation: `git ls-files '*.db'` is empty today; checked in task 3.1.
